## 4. Measures (computed by `python -m webtester evaluate`, never by hand)

Primary, with Holm correction over the three (`evaluate.PRIMARY`):

1. **Faults found** per run: reachable injected faults with a finding labelled with that fault.
2. **Precision per distinct issue** of B4's confirmed findings.
3. **Unique states** per run (exploration).

Secondary: precision per finding (raw, confirmed, judge-filtered), clean false alarms per run and per 100 armed checks
with exact intervals, recall per family and per primitive, mutation score, gate loss, tokens per confirmed true
finding, new (previously unknown) bugs, the funnel's first failed stage per missed fault.

Tests: two-sided Mann-Whitney U per primary measure, Vargha-Delaney A12 with a bootstrap interval; precision with
Clopper-Pearson intervals; false-alarm rates with exact Poisson intervals.

## 5. Targets (decided before the runs) **[U]**

| # | Target | Proposed | From |
|---|---|---|---|
| H1 | B4 finds more reachable faults than B0 and than B3v2 | p_holm < 0.05, A12 > 0.5 | ISSTA K1 |
| H2 | B4 detects at least this share of reachable faults (median over runs) | **>= 30%** | ISSTA K1 |
| H3 | Gate-confirmed precision per finding, B4 | **>= 0.80** | ISSTA K2 (development: 0.97-0.98 per finding on the resweeps, so a drop is expected) |
| H4 | Clean false alarms per run, B4 on the clean twin | **<= 1.0** | development limit 0.5, doubled for an unseen app |
| H5 | Gate recall loss (true findings rejected by the gate) | **<= 10 points** | ISSTA K5 |

A target missed is reported as missed. No threshold, rule or label changes in response to held-out results.

## 6. Reachability rule (before reading the faults)

A fault counts as reachable when the benchmark's own trigger can be performed through the UI with the seeded data
and the accounts in the config, without a literal that only the benchmark's test specification supplies (as
D32 for BookStack). The assistant applies the rule once, right after the lock, records each decision with its reason,
and the user checks it before the first run. Faults judged unreachable are reported, not hidden.

## 7. Labelling

The assistant labels every finding after the runs (D45, `by = "claude"`); unverified findings are labelled `fp`. The
user labels a blind random sample of 50 findings, stratified by condition; agreement is reported as Cohen's kappa
(ISSTA K8 target 0.6). Disagreements are settled by the user and recorded. New bugs are reproduced by hand before
they are counted.
